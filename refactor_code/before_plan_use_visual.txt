นอกจาก virtualized list แล้ว ถ้า feed มีทั้งรูป + วิดีโอ อยากลื่นแบบ Facebook ต้องโฟกัส 3 อย่าง:

วิธีเก็บ/ส่ง media (storage + CDN)

วิธีเข้ารหัส/แปลงไฟล์ (image / video pipeline)

พฤติกรรมบน frontend (lazy load, auto-play, pause, ฯลฯ)

ผมไล่ทีละชั้นให้แบบเอาไป implement ได้เลย

1. ชั้นฐาน: เก็บไฟล์ + ส่งไฟล์ยังไงให้ลื่น
✅ ใช้ Object Storage + CDN

ของคุณตอนนี้ใช้ R2 อยู่แล้ว = ดีมาก เหลือแค่:

ให้ domain ที่เสิร์ฟรูป/วิดีโอวิ่งผ่าน CDN เสมอ

ตั้ง cache header ให้ยาว ๆ เช่น Cache-Control: public, max-age=31536000, immutable สำหรับไฟล์ที่ชื่อมี hash (เปลี่ยนไฟล์ = เปลี่ยนชื่อ)

แนวคิด:
API (GoFiber) → ส่งแค่ metadata / URL
Static file (รูป/วิดีโอจริง) → เสิร์ฟจาก R2 + CDN โดยตรง
→ Backend ไม่โดนภาระหนัก

2. รูปภาพ: ใช้อะไร / ทำยังไงให้ลื่น
2.1 Next.js next/image (แนะนำสุด)

เพราะคุณใช้ Next.js + TS อยู่แล้ว:

ใช้ <Image> จาก next/image แทน <img>

มันช่วยให้:

lazy load อัตโนมัติ

ปรับขนาดรูปตามจอ (responsive)

ใช้ format modern อย่าง WebP/AVIF เมื่อ browser รองรับ

มี blur placeholder ได้

ตัวอย่าง:

import Image from "next/image";

<Image
  src={media.url}
  alt={post.title}
  width={800}
  height={800}
  className="w-full h-auto object-cover"
  sizes="(max-width: 768px) 100vw, 600px"
  loading="lazy"
/>


สำคัญ: ถ้าใช้ R2 domain นอกเหนือจาก origin ต้องไปเพิ่มใน next.config.js → images.domains

2.2 รูปอย่าเก็บ “ต้นฉบับใหญ่บ้าเลือด” ไว้ใช้ตรง ๆ

ควรมี image pipeline ประมาณนี้:

เมื่อ user upload → backend ส่งไปเก็บใน R2

แล้วทำอย่างน้อย:

resize หลายขนาด: thumbnail, medium, large

แปลงเป็น WebP/AVIF (ถ้าเหมาะ)

เก็บ metadata: width, height, aspectRatio

เวลา render feed:

ใช้ size ที่เหมาะกับ feed (เช่น 800px กว้างสุด)

ไม่ใช้ตัว original 5–10MB มาโชว์บนมือถือ

3. วิดีโอ: จุดที่ทำให้ fb ลื่นจริง ๆ คือ “streaming”

ถ้าอยากให้ feeling ใกล้ ๆ Facebook / TikTok:

3.1 อย่าปล่อย mp4 ดิบ ๆ ก้อนเดียว (progressive download) ถ้าคลิปเริ่มใหญ่

สิ่งที่ควรมี:

Video Streaming (HLS/DASH)

ไฟล์แปลงเป็น 240p / 480p / 720p / 1080p

player เลือกตามเน็ต user (adaptive bitrate)

รูปแบบไฟล์: .m3u8 + segments .ts หรือ .mp4 chunk

วิธีทำ:

ถ้าอยากง่าย ใช้บริการสำเร็จรูป:

Mux, Cloudflare Stream, ฯลฯ
→ คุณโยน mp4 ขึ้นไป, มัน generate streaming + thumbnail + API ให้เลย

ถ้าอยากทำเอง (เหนื่อยหน่อย):

ใช้ ffmpeg แปลงวิดีโอเป็น HLS แล้วเก็บใน R2

หน้าเว็บเล่นผ่าน player เช่น hls.js หรือ <video> + src HLS

3.2 บน frontend ใช้อะไรดี?

ตัวเลือกยอดนิยม:

สำหรับ HLS:

hls.js แล้วเอามาครอบ <video> เอง

สำหรับใช้ง่าย ๆ

react-player (รองรับหลายแหล่ง, ใช้ง่ายแต่ค่อนข้าง “อเนกประสงค์มากไปหน่อย”)

หรือใช้ <video> ตรง ๆ แล้วจัด behavior เอง

ตัวอย่างแบบ Next.js + <video> simple:

<video
  src={media.url}
  controls
  playsInline
  preload="metadata"
  className="w-full rounded-xl"
  poster={media.thumbnailUrl}
/>

4. Behavior ฝั่ง frontend ให้ “ลื่นแบบ fb”

นี่คือของที่ทำแล้วเห็นผลชัดมาก:

4.1 Lazy load รูป + วิดีโอ ด้วย IntersectionObserver

รูป/วิดีโอที่อยู่ไกลจาก viewport ไม่ต้องโหลดเลย

ให้โหลดเฉพาะ card ที่เข้าเขตมองเห็น (หรือใกล้ ๆ)

ตัวอย่าง pseudo code:

const ref = useRef<HTMLDivElement | null>(null);
const inView = useInView(ref, { rootMargin: "200px" }); // ใช้ react-intersection-observer ได้

return (
  <div ref={ref}>
    {inView ? (
      <ActualMediaComponent ... />
    ) : (
      <SkeletonMediaPlaceholder />
    )}
  </div>
);

4.2 Auto-play / pause วิดีโอแบบ Facebook

หลักการ:

auto-play เฉพาะ ตัวที่โดน focus อยู่บนหน้าจอ และ mute

ถ้า user scroll ผ่าน → pause ทันที

ไม่ควรเล่นหลายคลิปพร้อมกัน

Pattern ง่าย ๆ:

ใช้ IntersectionObserver เช็ค card แต่ละใบ

ถ้า inView && isVideo → videoRef.play() (mute + playsInline)

ถ้า !inView → videoRef.pause()

4.3 ควบคุม preload สำหรับวิดีโอ

อย่าปล่อย <video> preload เต็ม ๆ ทุกอัน
ควร:

preload="metadata" หรือไม่ใส่ → ให้ browser โหลดแค่ metadata

พอเข้า viewport จริง ๆ หรือ user กดเล่น → ค่อยเริ่มดาวน์โหลดหนัก ๆ

4.4 ใช้ metadata จาก backend มาช่วย UI + perf

เวลา user upload วิดีโอ/รูป → ควรให้ backend:

ดึงข้อมูล:

รูป: width, height, ratio

วิดีโอ: duration, width, height, ratio

เก็บใน media object แล้วส่งมาใน response

ตัวอย่าง:

{
  "type": "video",
  "url": "...",
  "thumbnailUrl": "...",
  "width": 1080,
  "height": 1920,
  "duration": 45
}


บน frontend:

ใช้ ratio คำนวณ height คร่าว ๆ (ช่วย virtualizer)

ใช้ thumbnail แทนวิดีโอจริงระหว่างโหลด

5. เชื่อมทุกอย่างเข้าด้วยกันแบบสรุป ๆ

ถ้าอยาก “เหมือน fb” แบบ version practical สำหรับคุณตอนนี้ (Next.js + Go backend + R2):

ภาพ

ทำ resize หลายขนาด (process ตอน upload)

ใช้ <Image> จาก next/image

ใช้ metadata width/height + aspect ratio ช่วย layout

วิดีโอ

เริ่มต้นอาจเสิร์ฟ mp4 + preload="metadata" ก่อน

มี thumbnail + duration ส่งมาด้วย

Frontend Behavior

ตัดสินใจ layout เอง (1 รูป / gallery / video)

รองรับ:

next/image

video auto-play/pause เมื่อ in-view

ใช้ metadata ช่วย virtualizer
